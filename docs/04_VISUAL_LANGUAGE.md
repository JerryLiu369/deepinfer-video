# 04 视觉语言

这份文件是"视觉词典"：每个概念用什么形状、什么颜色、怎么动。它的代码实现是 `manim_lib/dvlib.py`，两者必须一致——改词典就改代码，反过来也一样。

活样板：`examples/smoke`（EP99）渲染出来的关键帧。

## 1. 画面规格

- 1920×1080，30 fps，深色背景 `#0E1117`。
- 字体：中文 Noto Sans CJK SC；代码 Noto Sans Mono（可用 `DV_MONO_FONT` 换成 JetBrains Mono）。
- 字号（Manim `font_size`，指**最终上屏**的大小，缩放之后算）：镜头标题 40、副标题 24、正文 30–40、标签 18–22、条件行 20、代码 18–22。**小于 16 的字不上屏**（`dvlib.MIN_FONT`）。
  - `T()`/`M()` 收到小于 16 的字号会提到 16 并打 WARN。
  - 先排版后缩放也算：整组 `.scale(0.6)` 把 24 号字缩成 14 号，`check_layout()` 会报 `shown at font_size 14`。放不下时删字、拆屏或让框变大，不要整体缩小。

## 2. 版式

```
y= 4.0 ┌──────────────────────────────────────────────────────────┐
       │ 标题（左上，40 号）                 证据角标 · 范围标签（右上）│
       │ 副标题（24 号）                                            │
y= 2.3 ├──────────────────────── 主舞台 STAGE ─────────────────────┤
       │      x ∈ [−6.6, 6.6]，y ∈ [−2.75, 2.3]（dvlib.STAGE）       │
       │      主角放这里；数字卡、公式卡也放这里，不放到角落             │
y=−2.75├──────────────────────────────────────────────────────────┤
y=−2.9 │ ─────────── 字幕安全区：y < −2.9，不放任何元素 ─────────── │
y=−4.0 └──────────────────────────────────────────────────────────┘
        x=−7.1                                                x=7.1
```

- 底部 y < −2.9 留给字幕，即使是软字幕也不放东西（`SUBTITLE_SAFE_Y`）。
- 左右各留 0.3 的边距（`SAFE_X = 6.8`），文字不越过。
- 主舞台装不下时用 `fit_stage(mob)` 等比缩小到舞台内（只缩不放），缩完字号仍要 ≥ 16。
- 一屏最多 3 组同时运动的元素；一屏最多 7 个需要读的文字块。
- 左右对比时，左边是"不这么做"，右边是"DeepInfer 的做法"。

### 2.1 不许重叠（`check_layout` 自动检查）

`DVScene` 在每个 `until()` 和 `finish()` 时检查一次当前画面，发现以下情况打 `[dvlib] WARN … layout`：

| 检查 | 说明 |
| --- | --- |
| 字号 | 上屏字号 < 16 |
| 字压字 | 两个文字块包围盒重叠超过较小者的 10% |
| 字压图 | 文字与实心图形（填充不透明度 ≥ 0.3 的矩形/多边形，如 token 方格、矩阵格、Block）部分重叠；完全放在框**里面**的标签不算 |
| 出画 | 文字越过 `SAFE_X` 或贴到顶边；任何元素越出画面 |
| 字幕区 | 任何元素进入 y < −2.9 |
| 角标 | 任何文字碰到右上角的角标/范围标签 |

- 预览渲染要求 0 条 layout WARN；`render.py --quality final` 有 WARN 直接失败（`--allow-warn` 须在 `decisions.md` 说明原因）。
- 有意从画外滑入的元素用 `layout_exempt(mob)` 豁免，只限动画进行中，落位后不应再豁免。
- 调试时 `DV_LAYOUT=strict` 让第一条问题直接报错并给出位置；`DV_LAYOUT=off` 关闭（只限排查 dvlib 本身）。
- 这项检查只看包围盒。它抓不到"颜色太接近背景""箭头穿过文字"这类问题，审片仍要看帧。

### 2.2 数字卡、公式卡、说明卡

- 新卡片出现时，要么放在舞台的**空白处**，要么先把底下的图变暗（透明度 0.25）或移开。不允许直接叠在 token 行、矩阵上。
- `number_card()` 自带不透明底板，防止透出背后的图，但这只是兜底，不能代替上一条。

### 2.3 用满舞台

- 主角（图）至少占舞台高度的一半。矩阵、层堆这类图上屏至少 3.5 单位高，否则格子和标签都看不清。
- 一个元素占上半屏、下半屏空着时，把它放大或居中；半屏留白不是"简洁"。

## 3. 颜色语义（固定，不许换）

| 颜色 | 值 | 含义 | dvlib 常量 |
| --- | --- | --- | --- |
| 橙 | `#F0883E` | prefill、输入 token | `PREFILL` |
| 蓝 | `#58A6FF` | decode、输出 token、"当前关注" | `DECODE` |
| 绿 | `#3FB950` | 块状 KV cache | `KV` |
| 紫 | `#D2A8FF` | SWA 窗口、SWA 状态 | `SWA` |
| 金 | `#E3B341` | MoE 专家、EP | `EXPERT` |
| 浅蓝 | `#A5D6FF` | CPU 上的工作 | `CPU` |
| 浅绿 | `#7EE787` | GPU 上的工作 | `GPU` |
| 珊瑚 | `#FF7B72` | 投机解码的草稿 token | `DRAFT` |
| 红 | `#F85149` | 代价、浪费、错误、空泡 | `WARN` |
| 灰 | `#8B949E` | 次要信息、条件行、被裁掉的部分 | `MUTED` |

规则：

- 颜色只表达上面的含义。不要因为"好看"给一个框涂金色。
- "被省掉/被裁掉"的东西变灰（`MUTED`，透明度 0.25），而不是直接消失——让观众看到省了多少。
- 红色只给代价。每集红色出现的地方，就是"代价"段落。
- 一个概念的**描边、填充、标签**用同一种颜色：SWA 窗口框是紫色（`window_bracket` 默认），不是红色；要表达"这个窗口代价高"，在旁边加一个红色标签，而不是把窗口涂红。

## 4. 固定图形

| 概念 | 图形 | dvlib |
| --- | --- | --- |
| token | 小方块，一行排开；超过 30 个时一格代表一组，并标"每格代表一段 token（示意）"。逐格下标只放 1–3 个字符，长名称改成整行一条说明 | `TokenRow` |
| 窗口 / 区间 | 方块行上的描边框，上方标签 | `window_bracket` |
| GPU、机器、引擎、存储节点 | 圆角框 + 名称 + 灰色副标；框随文字自动撑开 | `Block` |
| 数据流 | 灰色箭头，标签写"传什么" | `arrow` |
| 时间线 | 泳道图，时间从左到右，泳道名在左 | `Timeline` |
| 一个请求的一生 | 六站小地图，当前站高亮；默认宽约 7.3，标签 16–18 号；`scale` 只缩放框，不缩字。只在站点切换时出现，不做常驻角落装饰 | `MiniMap` |
| 代码 | 深灰卡片，左上角是 `路径:行号`，高亮关键行；代码 ≥ 18 号、路径行 ≥ 16 号，放不下就少摘几行 | `code_panel` |
| 数字 | 大号数字 + 单位 + 灰色条件行，自带不透明底板 | `number_card` |
| 证据等级 | 右上角药丸：`A 代码证实` / `B 官方文档` / `C 第三方实测` / `D 社区说法` / `E 推断/示意` | `DVScene` 自动加 |
| 范围 | 右上角药丸：`开源代码里有` / `仅文档描述 · 未开源` / `代码 + 文档` / `通用概念` | `DVScene` 自动加 |
| 40 层立体分层 | 40 个细长横条竖排，支持 split 留缝与分段着色；分段用 `range_label(a, b, "第 1–20 层")` 标注（EP03、EP07） | `LayerStack` |
| 注意力网格 | n×n 方格，SWA 带状可见域与列截断掩码；上屏必须带 `axes()` 行列说明，高度 ≥ 3.5（EP07） | `AttentionMatrix` |
| 代价天平 | 三角支点 + 横梁 + 左右托盘；托盘字 22 号、一行 ≤ 8 字，托盘随字撑开（EP07 及每集代价段） | `Scale` |

需要但还没有的组件（由 animator 在后续阶段实现进 `dvlib.py`，实现后在这里登记）：

- `SourceMap`：三源头图（模型 / 部署 / 生产），可点亮（每集）
- `ExpertGrid`：GPU × 专家的网格（EP08）
- `CompareCard`：vLLM / SGLang / DeepInfer 三栏对照（EP05–EP12）
- `ParetoChart`：带条件注释的二维曲线（EP08、EP12）

## 5. 动效节奏

- 动作跟着旁白走：用 `until("cue")` 对齐到旁白里的 `[#cue]`，不写死秒数。
- 一个动作 0.4–1.2 秒。超过 2 秒的连续动作要有理由（例如窗口滑过一整行）。
- 揭晓（aha）之前留 0.5–1 秒静止（在旁白里加 `[pause:0.8]`）。
- 转场只用淡入淡出和位移；不用旋转、缩放炸开、3D 翻转。
- 镜头之间不做转场动画，直接切；集内大段落之间用 1.5 秒的段落卡（大号标题）。
- 不用背景音乐盖住旁白；如果用，音量 −30 dB 以下（`assemble.py --bgm`）。

## 6. 真实性规则

1. **示意要标示意。** 方块数、条长等象征性比例，屏幕上标"示意"或"每格代表……"。
2. **真实比例要真实。** 声称"按比例"的图（计算量对比、字节数对比），比例必须来自 `work/calc/` 的计算结果。
3. **代码卡片要真实。** 原文摘录：路径、行号与固定 commit 一致，不超过 10 行。改写成伪代码时，路径后面加"（示意，非原文）"。
4. **图表要有出处。** 每张图右下角灰色小字写来源与条件。"示意"脚注和出处放在舞台底边之上（y ≥ −2.75），不要放进字幕区——试点 EP07 有 6 个镜头的"示意：…"脚注被字幕盖住。
5. **角标与内容一致。** 镜头元数据的 `badge` 取本镜头引用事实里最弱的那一级（lint 会提醒）。

## 7. 审片看什么（art-director 用）

- 三米外（缩略图）能不能看出这一屏的主角？
- 颜色有没有违反第 3 节？
- 字有没有小于 16、超出画面、压到字幕安全区、和别的元素重叠？（先看渲染日志里的 layout WARN，再看帧；日志无 WARN 不等于没问题）
- 主角够不够大？舞台有没有半屏空着？矩阵、层堆有没有行列/分段说明？
- 同一个概念在不同镜头里是不是同一种画法？
- 画面有没有在念旁白（屏幕字和旁白一样）？
- 关键帧里是否出现了旁白还没讲到的结论（剧透）？
