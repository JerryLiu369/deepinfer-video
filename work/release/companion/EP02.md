# 观看手册 · EP02 DeepInfer 是什么，不是什么

> 一页纸。所有代码入口与事实均来自 `work/facts/EP02.yaml` 与 `work/facts/GLOBAL.yaml`。

## 三句话

1. DeepInfer 开源的是生产引擎的离线推理部分：专为单一模型 DeepSeek-V4.1-Flash 定制，官方仅支持英伟达 SM100 与华为昇腾 950 双硬件。（F02-01, G-02, G-05）
2. 完整在线云服务还缺失三项关键基建：分布式 KV Cache 存储、VE/Prefill/Decode 三段物理分离部署、以及跨副本在线负载均衡；源码中完整保留了对接这些系统的“架构插槽”。（F02-03, F02-07）
3. DeepSeek 的真实生产系统采用 E/P/D 三段分离与独立 3FS 存储集群；其设计目标是在多厂商硬件上，以 128 卡最小高效单元实现 KV 留存 72 小时以上的大规模高吞吐服务。（F02-04, F02-05, G-07）

## 本集的"为什么"

| 机制 | 源头（模型 / 部署 / 生产） | 换来什么 | 付出什么 |
| --- | --- | --- | --- |
| 仅支持 V4.1-Flash 单模型 | 模型结构 | 极致定制专用算子（TileLang）与内存排布，消除通用抽象开销 | 丧失框架通用性，无法直接跑其他主流开源模型 |
| E/P/D 三段分离部署 | 部署形态 | 算力受限（Prefill）与带宽受限（Decode）物理隔离，消除资源争抢 | 引入跨机 KV Cache 传输网络，增加了系统部署复杂度 |
| 专用 3FS 集中式存储 | 部署形态 | 任何 Prefill 节点均可命中任意前缀，计算节点故障不丢 KV 缓存 | 极高的网络带宽要求（每 8 卡 400 Gbps）与存储节点投资 |
| 架构插槽（虚函数与枚举） | 生产需求 | 剥离强耦合基础设施代码，使开源离线引擎保持轻量便携 | 开源版本身无法直接作为在线服务开箱即用 |
| deepseek-recipe 独立分仓 | 生产需求 | 将协议转换、安全防注入与流式解析解耦至 Rust 高性能库 | 引擎调用需维护跨语言接口依赖 |

<summary>自测题答案</summary>

1. 不能。因为开源发布明确界定为离线推理框架（Offline Inference），全仓不包含 HTTP 网关、请求排队、路由转发等在线服务模块，仅提供单机本地批处理运行脚本（`LLM.generate`）。（S01, S03, S07 / F02-01, F02-03）
2. 缺失三项基建：① 分布式 KV Cache 系统；② VE/Prefill/Decode 三段物理分离部署机制；③ 跨数据并行（DP）副本的在线负载均衡器。这些组件因与内部机房基础设施深耦合而未开源。（S06, S08 / F02-03, F02-11）
3. Prefill 节点采用算力受限的标准 8 卡服务器（EP2–8），因为其核心瓶颈是长提示词的大矩阵计算；Decode 节点采用 64–128 卡超节点并运行宽专家并行（Wide-EP），因为自回归每步生成受显存带宽限制，通过将专家分散到数十张卡上能大幅削减单步访存量，显著提升吞吐。（S09, S10 / F02-04, G-07）
4. 这是 DeepSeek 在单一生产集群中取得的极限吞吐成绩（平均每秒约 179 万 Token）；每卡每小时 38 美元是按照官方公布的“谷时优惠定价”测算的“整体营收”（Revenue），并非净利润，且依赖 128 卡以上的大规模专用超节点与 3FS 存储支持。（S12 / F02-06, G-04）
5. 因为引擎内部已经把分布式部署所需的状态机、调度接口和显存缓存槽位完整做成了“架构插槽”：代码中有 `EngineType` 三态、7 个空实现的虚函数骨架、C++ 移交注释（`prefill_engine ... transferred to complete_engine`）以及显存副本缓冲区 `copy_state`。引擎随时可以被外部基础设施子类所继承接入。（S15, S16 / F02-07, F02-08, F02-09）
