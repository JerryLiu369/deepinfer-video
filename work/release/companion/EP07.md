# 观看手册 · EP07 SWA 有界重放：只重算最后一小段

> 一页纸速查。所有代码入口与数字均来自事实账本 `work/facts/EP07.yaml` 与固定 commit `9bd9cf2`。

## 三句话

1. **精确重建很贵，有界重放做近似**：V4.1-Flash 的 40 层都是 128 窗口的滑动窗口注意力（SWA），多层叠起来感受野向左扩散，精确重建 decoder 层的 SWA KV 需要把最后 2,560 个 token 跑过 20 层；有界重放只重算末尾一小段，并强制截断注意力区间，将重算代价压为常数（F07-02, F07-03）。
2. **两处用法与计算量减半**：用于前 20 层缓存命中时的 SWA 状态补算，以及后 20 层的每次 prefill；后 20 层仅保留末尾 KEEP_TOKENS 行（README 配 140，代码要求 ≥ 128 + 6），理论上使 prefill query 行数从 40 万减少至 20.28 万（约 50.7%）（F07-04, F07-05, F07-10）。
3. **测试等价 ≠ 精度无损**：开源仓库的 `yoco_equiv.py` 仅比对 mask 与 compact 两种截断写法是否一致，并未比对截断与不截断的数值差异；官方定性说明影响可忽略，并在后训练中模拟同样的重放完成适配（F07-09, F07-11）。

<summary>自测题答案</summary>

1. **答**：每层滑动窗口大小为 128，由于后 20 层逐层向上堆叠，上层依赖下层的 128 个位置，下层又各自依赖更早的 128 个位置，感受野向左扩张。在官方部署问答口径中，20 层乘算恰好为 $20 \times 128 = 2,560$ 个 token。（出处：S05 / F07-02）
2. **答**：公式为 $\max(s, i-127) \dots i$。在重放起点 $s$ 之前的所有历史 token 均被强制屏蔽不可见，因此无论输入上下文是 1 万还是 10 万 token，后 20 层实际参与前向的 query 始终只有最后 KEEP_TOKENS 行，与总长度彻底脱钩。（出处：S06 / F07-03）
3. **答**：有两个关键原因：第一，交界层（第 20 层）在删行前必须先对全部 10,000 行做全量 attn_norm 与 KV 投影；第二，行数不等于算力（FLOPs），且推理受显存带宽与通信影响，因此计算量减半不等于端到端延迟减半。（出处：S10 / F07-08, F07-10）
4. **答**：启动时会触发 Python 断言失败崩溃。因为代码强制要求 `window_size + MAX_BACKTRACKING_TOKENS <= KEEP_TOKENS`，默认配置下 $128 + 6 = 134 > 128$。（出处：S08 / F07-05, F07-06）
5. **答**：不能。测试比对的是 mask 模式（盖住）与 compact 模式（删行）在同样截断条件下的 bitwise 一致性，并没有比对截断与全量计算的数值误差；官方定性说明影响可忽略并依靠后训练适配。（出处：S11 / F07-09, F07-11）
