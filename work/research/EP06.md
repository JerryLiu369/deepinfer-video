## 1. 最重要的 3–5 个发现

1. **代码里有三个完全不同的"128"，绝不可混用**（F06-01）：① 逻辑块 token 容量 `block_size = 128`；② 状态落盘步长粒度 `KVSTORE_GRAIN = 128`；③ 显存物理与算子硬件对齐 `128 字节`（DeepGEMM / MXFP8）。
2. **StateBlock 槽位采用"前存后丢"布局与 134 窗口**（F06-08、F06-09、F06-11）：每个槽位低地址为存储区（前 20 层 SWA 环），高地址为丢弃区（后 20 层 consumer SWA 与压缩边界累加器）。推理环为 134 = 128（滑窗）+ 6（投机回退预算）。落盘时按前缀截断，每序列落盘数据量严格固定为 20 × 134 × 528 = 1,415,040 字节（1.35 MiB），与序列长度 L 完全无关。
3. **开源版没有任何自动前缀缓存**（F06-16、F06-17、F06-18）：`BlockManager` 纯粹是 FIFO 空闲双链表加引用计数，无 Hash、Radix 树或 LRU 淘汰机制。显存内唯一共享原语是显式 `fork_seq`（pin 块表 + COW 复制末块 + 克隆 state）。匹配在未开源的 Entrypoint 做，持久化在专用 3FS 集群，开源树仅暴露增量注入端口。
4. **两套独立 BlockManager 联合准入控制**（F06-06、F06-07、F06-14）：一套管理变长分页 KV 块，一套管理定长 StateBlock 槽位。显存规划优先扣除 2 倍 state 内存（为 state store 与 copy buffer 预留），剩余显存再除以每块字节数得到 GPU 块数。
5. **块在显存中是一维扁平连续字节带**（F06-03、F06-04、F06-05）：块不是"每层一个独立张量"，而是一维 uint8 字节切片，层内 32 字节对齐，整块按 `lcm(128, bytes_per_token)` 对齐（FP4 1152 B，MXFP8 4224 B）。

## 3. 观众最容易误解的地方

| 误解 | 真相 | 事实 ID |
| --- | --- | --- |
| 以为 SWA 状态也像 KV cache 一样存入 3FS 持久存储 | 官方文档明确说明：SWA 状态只留在产生它的本地主机内存中（单副本约 1.4 MB），绝不进 3FS！跨机命中走 400G VLAN 拉取；只有全局块状 KV 进 3FS | F06-19 |
| 以为 134 是随意选取的经验常数 | 134 = 128 + 6，其中 128 是模型 SWA 注意力滑窗，6 是最大回退预算（MAX_BACKTRACKING_TOKENS，即 nextn 投机解码 5 + 1），容忍回退与滞后 | F06-09 |
| 以为所有 40 层的 SWA 状态都要落盘保存 | 只有前 20 层（encoder 阶段）的 SWA 环进入存储区；后 20 层（decoder 阶段）复用第 20 层全局投影，其 SWA 状态在丢弃区，不落盘 | F06-08, F06-11 |
| 以为开源版能够跨请求自动共享重复 prompt | 开源版 BlockManager 无哈希索引，相同 prompt 无法自动识别；显存内唯一共享原语是显式的 Scheduler.fork_seq（多分支采样基准测试用） | F06-16, F06-17 |

## 4. 与大纲的出入

| 大纲说法 | 核验结果 | 建议改法 |
| --- | --- | --- |
| 大纲称"命中上限是 L - 134" | 源码与文档指出：落盘粒度按 128 整数倍截断，末尾保留 1 个 token，最少需保留完整的 134 窗口，因此外部前缀命中注入的理论上限严格受限于末尾 134 token 补算 | 在解说中清晰说明 L - 134 的物理来源（L 必须扣减最后一个未满 128 块以及 134 窗口重放要求） |
| 大纲未提及显存规划中的双倍 state 预留 | 源码 base.py:243 明确硬编码 `state_size *= 2`（state store & copy buffer） | 将双倍预留机制作为显存规划容量推演的核心关键点明确呈现 |

## 5. 可视化素材

- **时序步骤**：
  1. 准入联合检查：同时向 block_manager 申请 KV 块、向 state_manager 申请槽位。
  2. 显存写入：TileLang store_kv_cache 内核按一维 slot_mapping 写入扁平字节带。
  3. 解码步进：每次跨越 128 token 边界触发快照更新，末尾 134 窗口保持完整。
  4. 释放回收：请求结束，整张块表引用计数归零入 FIFO 链表，state 槽位归还。
- **数据表（附 calc 脚本）**：
  - `work/calc/EP06_bytes.py`：FP4 Main KV 288 B、MXFP8 Main KV 528 B、FP4 Index 68 B、MXFP8 Index 132 B、SWA 528 B；对齐 lcm(128, 288) = 1152 B、lcm(128, 528) = 4224 B、lcm(32, 528) = 1056 B。
  - `work/calc/EP06_state_disk.py`：每序列落盘 `20 × 134 × 528 = 1,415,040 B`（1.35 MiB）；推理环 134 token，kvstore 环 262 token；max_num_seqs=256 时槽位数 308。
  - `work/calc/EP06_capacity.py`：80 GiB 显存规划实测推导，峰值扣除与双倍 state 扣除，得出可用块数与 80% 安全序列长度约束。
- **结构关系**：
  - StateBlock 内部切分：`[存储区: 前20层SWA环 1.4MB] | [丢弃区: 后20层Consumer SWA环 + 逐层ica/ca压缩边界]`。
  - 三层存储架构立面：`GPU HBM (在飞) -> 本地 Host 内存 (SWA单副本 1.4MB) -> 3FS 集群 (分页块KV)`。
