# EP03 研究简报（独立核验 b）

## 0. 元信息
- 代码：`deepseek-ai/DeepInfer` @ `9bd9cf2`（2026-10-21）。
- 模型：`deepseek-ai/DeepSeek-V4.1-Flash-1017` 的 `config.json`、48 个 shard 的 safetensors 头部、HF API 元数据。
- 官方文档：`doc/inference_deployment_qa.md`；官方技术报告：arXiv 2609.19969（2026-09-17）。
- 账本：`work/facts/_alt/EP03_b.yaml`，30 条：A 16（verified 5 / caveat 11）、B 8（verified 1 / caveat 7）、E 6（全部 caveat）。
- 计算脚本：`calc/EP03_params_b.py`、`calc/EP03_kv_b.py`、`calc/EP03_state_b.py`。

## 1. 最重要的 5 个发现
1. **763.2B 总参数里 196.9B 是查表**：Engram 两层表 196.93B（25.8%），路由专家 543.58B（71.2%）；官方报告说的 552B 是“backbone”，约等于 763.2B 减去 Engram、MTP、视觉/aligner（F03-07、F03-08、F03-19）。
2. **40 层里只有 4 层产生块状 KV**：2/8/14/20 持有投影权重，其余层按 `layer_kv_map` 复用；摊到每输入 token 正好 890 B（F03-04、F03-13）。
3. **CED 让 prefill 只跑 encoder 半区**：第 20 层从 encoder 末层 hidden 投出 decoder 全局 KV，21–39 复用；官方口径 decode 16B、prefill 8B 激活参数（F03-03、F03-08、F03-27）。
4. **state 槽是固定开销**：主干 40 层 2,830,080 B；加上 3 个 DFlash 草稿层与 3 个 C2 压缩状态，整槽 3,128,928 B（2.98 MiB），与上下文长度无关（F03-16）。
5. **每个 token 只读 24 行 Engram**：3 个 n-gram 阶 × 8 head × 256 维 = 6,144 个值；196.9B 参数绝大部分不参与当前 token 的计算（F03-20）。

## 2. aha 候选
- **“40 层只有 4 层留长期 KV”**（A/B，F03-04、F03-13）
  - 为什么反直觉：直觉是“每层都有自己的 KV”；实际 2–7 共用 2 层、8–13 共用 8 层、14–19 共用 14 层、21–39 共用 20 层。
  - 怎么画：40 层竖排，逐层点亮“Full / Reuse / Reindex / 纯 SWA”，最后只留 4 条向下的 KV 竖线。
  - 注意：这 4 层是“块状 KV”；SWA 状态仍是每层一份，别把两句话混成“只有 4 层有状态”。
- **“763B 的模型，只有 16B 激活”**（B，F03-07、F03-08、F03-09）
  - 为什么反直觉：196.9B 是查表，543.6B 是 384 选 6 的专家；每 token 真正过的矩阵乘约 16.4B 参数。
  - 怎么画：763.2B 的堆叠条，把 Engram 标成“查表”、路由专家标成“384 选 6”，再拉出 16.4B 的激活条。
- **“短上下文时，状态缓存反而更贵”**（E，F03-16、F03-18）
  - 为什么反直觉：块状 KV 是 O(L)，state 是 O(1)；L 很小时 O(1) 反而更大。
  - 数字：3,128,928 / 890 ≈ 3,516 token；只用主干 40 层是 3,180 token。
  - 怎么画：两条直线，交叉点标注“约 3.5K token（按整槽口径）”；右下角写“示意：只比 HBM 占用”。
- **“3 层草稿，不等于每步猜 3 个”**（A/B，F03-21）
  - 为什么反直觉：`num_nextn_predict_layers=3` 是堆叠层数，`USE_NEXTN_DECODE=5` 是每步草稿宽度；两个数独立。
  - 怎么画：3 个方块竖着叠，旁边 5 个位置横着排；标“3 层 × 5 位置”。

## 3. 观众最容易误解的地方
| 误解 | 真相 | 事实 ID |
| --- | --- | --- |
| 40 层全是纯 SWA | 每层都有 SWA，但第 2–39 层还有 CSA2 压缩全局 KV；只有 0–1 层是纯 SWA | F03-01、F03-02 |
| 只有 4 层有 KV | 4 层产生块状 KV；43 个 SWA 层各有自己的窗口状态 | F03-04、F03-16 |
| 890 B 是“总 KV” | 890 只含块状 main+index；SWA 状态另算，且是每序列固定 | F03-13、F03-16 |
| 763B 参数都要过矩阵乘 | 196.9B 是 Engram 查表，543.6B 是 384 选 6 的专家；每 token 激活 16.4B | F03-07、F03-09、F03-20 |
| 3 层 MTP = 每步 3 个草稿 | 3 是层数，5 是草稿宽度；两个独立超参 | F03-21 |
| FP4 就是 E4M3 | 主 KV 数据是 E2M1，E4M3 是每 16 个值的 scale；没有全局 scale | F03-10 |
| top-512 是 512 个原始 token | 512 是压缩 token 条数；C2 层每 2 个原始 token 才压出 1 条 | F03-30、F03-02 |
| 552B 是媒体瞎写 | 552B 是官方报告的 “backbone” 口径；763.2B 含 Engram/MTP/视觉 | F03-08 |
| CED 是代码里的名字 | CED 是报告术语；代码里是 `n_prefill_layer` 与 `yoco consumer` | F03-24 |

## 4. 与大纲的出入
1. **“SWA 状态每序列约 2.8 MB”**
   - 核验：2.83 MB（十进制）只是主干 40 层；整槽还含 3 个 DFlash 草稿层的 SWA 与 3 个 C2 压缩状态，共 3,128,928 B ≈ 3.13 MB（2.98 MiB）。
   - 建议：旁白写“主干 40 层约 2.8 MB；整槽约 3.1 MB”，或统一用“约 3 MB”。
2. **“前 20 层（encoder）对全序列算 KV”**
   - 核验：前 20 层确实在全序列上运行，但只有 2/8/14 三个 CSA2 Full 层投影 encoder 块状 KV；第 20 层再投影一份 decoder 共享 KV；其余层复用各自分组的 KV。
   - 建议：改成“前 20 层在全序列上跑；块状 KV 只由 2/8/14/20 四层产生”。
3. **“40 层全部是 128 窗口的 SWA”**
   - 核验：作为“每层都有 SWA”成立；作为“只有 SWA”不成立。第 2–39 层同时有 CSA2 分支，0–1 层才是纯 SWA。
   - 建议：补一句“每层都有 SWA，但 38 层还挂着压缩全局 KV”。
4. **“Engram 占参数四分之一”**
   - 核验：196.93/763.2 = 25.8%，成立；但如果用官方 552B backbone 做分母，则是 35.7%。
   - 建议：明确分母是 763.2B 总参数。
5. **“交叉点在约 3,277 token”**
   - 核验：3,277 用的是 2,916,672 B（40 层 + 压缩状态，漏了 3 个草稿层）。用整槽 3,128,928 B 得 3,516；只用主干 40 层得 3,180。
   - 建议：旁白说“约 3,200–3,500 token（取决于是否把草稿层算进 state）”，或统一用整槽口径 3,516。
6. **“总参数以 HF config.json 推算为准”**
   - 核验：config 给出层数/专家数/Engram 行数与行宽，但总量最好用 HF 权重元数据 `total=763,205,315,794`；官方报告另给 552B backbone。
   - 建议：屏幕上同时给“763.2B 总参数 / 552B backbone / 16.4B 激活”三个数，并标口径。
7. **R02b 笔记的 Engram 体积有误**
   - 核验：R02b 把行宽写成 8×256=2048，得出 786 GB/层、1.57 TB；实际权重是 `[384006168, 256]`，每层约 98.3B 参数/98.3GB FP8，两层 196.9GB。
   - 建议：不要引用 1.57 TB；用 196.9B 参数/196.9GB FP8。

## 5. 可视化素材
### 5.1 40 层结构表（可直接做层柱）
| 层 | 数量 | ratio | 类型 | 块状 KV 源 | index 模块源 |
| --- | --- | --- | --- | --- | --- |
| 0–1 | 2 | 0 | 纯 SWA（128） | — | — |

### 5.3 state 槽布局（每序列）
```
[stored: 20 层 × 134 × 528 B = 1,415,040 B]  ← 落盘
[dropped: 23 层 × 134 × 528 B = 1,627,296 B
          + 3 层 C2 state × 7×2×512×4 = 86,016 B]  ← 不落盘
整槽 = 3,128,352 B → 对齐 1,056 B → 3,128,928 B
```
- 依据：F03-16、F03-17、F03-28；`calc/EP03_state_b.py`。
- 注意：dropped 的 23 层 = 20 个 decoder 主干层 + 3 个草稿层。

### 5.4 参数分项（饼图/堆叠条）
`543.58 / 196.93 / 14.23 / 5.13 / 1.42 / 1.32 / 0.49 / 0.12`（B）
- 路由专家 / Engram / MTP / 注意力（含 indexer） / 共享专家 / embed+head / 视觉+aligner / gate+HC。
- 依据：F03-07；`calc/EP03_params_b.py`。

### 5.5 两条曲线
- 块状 KV：890 B × L。
- state：3,128,928 B（固定）。
- 交叉：3,516 token；主干 40 层口径 3,180 token。
- 依据：F03-18；`calc/EP03_state_b.py`。

### 5.6 MTP 3 层 × 5 位置
- 3 个草稿层纵向堆叠，每层对同一组 5 个位置做前向；Markov 头在采样时补 token 间依赖。
- 依据：F03-21、F03-22；论文 §2.4.3。

### 5.7 Engram 的 24 次查表
- 3 个 n-gram 阶（2/3/4）× 8 个 head，每个 head 在约 16M 桶的表里取一行 256 维；每 token 每层 24 行。
- 依据：F03-19、F03-20；论文 §2.4.2。

### 5.8 CSA2 的稀疏选择
- 每个 query 选 top-512 个压缩 KV；第 20 层先选 2,048 个 8-token block（16,384 个候选位置），24/28/32/36 只在候选池内重选。
- prefill 时单 query 最多看 128（SWA）+ 512（压缩）= 640 个 key。
- 依据：F03-30、F03-04；论文 §2.3.2。

## 6. 未解决问题
1. **为什么 decoder 用 C1（不压缩）、encoder 用 C2（2:1）？**
   - 已查：论文 §2.3.1/§4.2.1 只给模式，没给理由；代码 `compress.py` 只断言 C1/C2 支持。
   - 建议口径：说“官方只给了结构，没有解释取舍”；不要编“因为 decoder 更该省”。
2. **552B 的精确构成**
   - 已查：论文只给 552B；按权重元数据减 Engram/MTP/视觉/aligner 得 551.57B，差 0.43B 可能来自舍入或未分类小项。
   - 建议口径：写“约 552B”，不要写 551.57B 上屏。
3. **state 槽到底报 2.8 还是 3.1 MB**
   - 已查：2,830,080 B 是 40 个主干层；3,128,928 B 是含 3 个草稿层的整槽。代码 `swa_num_layer` 遍历整个 `attn_module_list`，含 DFlash。
   - 建议口径：旁白说“主干约 2.8 MB，整槽约 3.1 MB”；如果只能留一个数，用 3.1 MB 并说“含草稿层”。
4. **论文 §2.2 的“每层 KV 投影”与 checkpoint 只有 4 个 compressor 权重**
   - 已查：论文 Eq.(1) 写 `W_l^KV` 每层不同；HF 权重只有 2/8/14/20 有 `attn.compressor.*`；§2.3.1 的 Full/Reuse 模式解释了共享。
   - 建议口径：以 checkpoint/代码为准，说“第 20 层投出 decoder KV，21–39 复用”；不要按 Eq.(1) 讲成“每层都投一份”。
5. **`dspark_block_size` 与 `USE_NEXTN_DECODE`**
   - 已查：config 有 `dspark_block_size=5`，代码运行时用 env `USE_NEXTN_DECODE`，没有 assert 两者相等。
   - 建议口径：讲“默认都是 5”，并说明“env 可改，权重按 5 训练”。
6. **mHC 的“m”与 YOCO 的字母展开**
   - 已查：论文只写 “Single-Pass m HC”“YOCO (Sun et al., 2024)”，代码只有 `hc_*`/`yoco`；没有展开。
   - 建议口径：只说“官方叫 Single-Pass m HC / YOCO”，不要自行展开。
7. **变长验证是否默认开启**
   - 已查：`DEEPINFER_ENABLE_MTP_VARLEN = EnvVar.bool()` 没有默认值；文档描述生产用变长验证。
   - 建议口径：讲“代码里有这条路径，是否默认开启未确认”；EP09 再定。
