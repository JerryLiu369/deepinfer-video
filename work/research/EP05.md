## 1. 最重要的 5 个发现

1. **ZOS 核心是"CPU 永远晚一步"以掩盖调度开销**：当 GPU 执行第 N 步模型计算（Forward）时，CPU 并发处理第 N-1 步的后处理，并调度准备第 N+1 步。GPU 流水线一刻不停，代价是 CPU 在做决策时无法预知上一步的实时输出（F05-01、F05-03、F05-05）。
2. **CPU 根本不为存量命中请求构造输入 token**：针对上一轮已经在批次中的存量请求，CPU 端写入 0 字节；底层由 GPU 上的 TileLang 内核 `gather_input_ids_zos` 直接从上一轮的 `prev_sampled_token_ids` 与预测 token 中就地捡出（F05-06）。
3. **ZOS 仅在连续 decode 步生效，prefill 步仍是纯同步的**：只要出现 prefill 步，系统就会当场同步两次后处理并排空异步流水线；prefill 之后的首个 decode 步也因无前序步而无法重叠。ZOS 专注于为长序列 decode 提供无空泡加速（F05-04）。
4. **官方文档声称的"prefill 二次代价模型 + 时间预算"在代码中完全缺失**：文档里的 `compute_quota_limit` 和二次时间求解在代码中 0 处实现；开源版的 prefill 仅基于硬 token 预算和图片边界裁剪。代码中唯一的二次项是 `FlopsEstimator`，仅用于日志 MFU 记账（F05-14）。
5. **结束请求（EOS）的多跑一步是确定性的固定代价**：因为 CPU 滞后一步不知道请求输出了 EOS，第 N+1 步仍会将其送入 GPU 跑一次多余前向，随后在第 N+1 步后处理中丢弃结果，第 N+2 步释放。量化推导证明：500 token 生成下多跑 1 步仅浪费 0.2% 算力，换来每步消除 24.6% 的空泡（F05-08、F05-21）。

## 3. 观众最容易误解的地方

| 误解 | 真相 | 事实 ID |
| --- | --- | --- |
| ZOS 是 DeepSeek 独创的技术发明 | 官方文档明确注明参考了 NanoFlow 与 SGLang 的重叠流水线思想，并非 DeepInfer 首创 | F05-18、F05-20 |
| ZOS 让整个推理系统（包含 Prefill）都变成全异步 | Prefill 步强制同步执行，只有连续的 Decode 步之间才产生重叠 | F05-04 |
| 异步调度下 GPU 选取的每步 Token 数量随时随机变动 | Decode 阶段受 CUDA Graph 桶大小和 CPU 总预算 `best_bsz` 硬约束，总 Token 数必须保持恒定 | F05-10、F05-15 |
| 遇到 EOS 还要多跑一步是严重的工程 bug | 这是异步流水线不可避免的固定代价；量化证明损失仅 0.2%，相比消除 25% 空泡是压倒性净收益 | F05-08、F05-21 |
| decode 调度依然遵循公平的先进先出（FIFO）原则 | Decode 采用 LCFS（输出最短优先），显存紧张时抢占最老的请求并直接判死中断 | F05-12 |

## 5. 可视化素材

1. **同步 vs ZOS 时间线对比图**（Timeline 组件）：
   - 同步路径：Forward(N) → Sample(N) → [GPU 空转 1.5ms] → Forward(N+1)。
   - ZOS 异步路径：GPU 连续执行 Forward(N) → Sample(N) → Forward(N+1)；CPU 在 Forward(N) 期间执行 Post(N-1)，在 Sample(N) 期间执行 Schedule(N+1)。
2. **GPU 就地捡词动画**（TileLang gather 内核）：
   - CPU 侧 `fresh_input_ids` 仅对新请求（remap=-1）写入数据。
   - GPU 显存内，存量请求行通过 `prev_sampled_token_ids` 与 `prev_predict_token_ids` 由 TileLang 内核直接 gather 组合出 `input_ids`。
3. **EOS 滞后一步与代价天平**（Scale 组件）：
   - 动画演示第 N 步生成 EOS，第 N+1 步多跑一次前向，随后标记丢弃并在第 N+2 步释放。
   - 代价天平：左托盘放 0.2% 额外计算浪费，右托盘放 24.6% GPU 空泡消除与 30% 吞吐提升，天平瞬间重重倒向右侧。
4. **DSpark 变长验证分工图**：
   - 上半部分：CPU 查 `DecodePerfCache` 延迟曲线，计算最佳吞吐点并锁定总预算 `best_bsz`。
   - 下半部分：GPU 内核按置信度重算每个请求的 `seqlen_q`，总和恒等于 `best_bsz`，D2H 写回 pinned 内存。
