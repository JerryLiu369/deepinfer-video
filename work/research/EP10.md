## 1. 最重要的 4 个发现

1. **5 大外部内核库与极薄的双硬件同名镜像（F10-01, F10-02, F10-03）**：
   - DeepInfer 的算子底座由 5 个外部库（FlashMLA 负责注意力、DeepGEMM 负责矩阵乘与 MQA logits、DeepEP 负责专家通信、TileKernels 负责门控与量化、DeepSelect 负责 TopK）加仓库自研的 TileLang 算子构成。
   - 双硬件差异被严格隔离在最薄的一层：构建期通过 `scripts/build_vendor.sh` 二选一安装同名 wheel，TileLang 在 `cuda/` 和 `asc/` 分别维护 43 个同名 `*_tl` 算子工厂，通过 `ops.py` 实现纯名字级重导出，上层模型代码实现 0 分支。
2. **批不变性的物理本质是消除批维度的归约树依赖（F10-06, F10-07, F10-08, F10-09）**：
   - 浮点加法非结合律 `(a+b)+c != a+(b+c)` 使得 GPU 动态调整归约树分块时产生舍入漂移。
   - `DEEPINFER_BATCH_INVARIANT=1` 不是高深算法，而是一串外科手术般的开关：关掉 FlashMLA 的 split-KV（由单 CTA 串行扫完 topk）、DeepGEMM 禁用 cuBLASLt 与 mega-gate split-K、EP 关多次归约；采样器改用"一行一个 CTA"使归约树只由词表大小决定，top-p 采用 2^31 定点整数直方图消除浮点累加误差。
3. **确定性采样的绝对坐标与变长 MTP 的破坏性权衡（F10-10, F10-11, F10-12, F10-13）**：
   - 确定性采样的核心不是固定全局种子，而是 RNG 下标是"绝对 token 位置"（`sample_positions = seqlen_k`），即使发生抢占重算、前缀复用或位置漂移，随机流也绝对对齐；每个位置划分 3 条独立随机子流，并对 MTP 草稿引入 `1000000007` 偏移。
   - 变长 MTP 会按全批置信度全局排名动态分配验证长度（`extra_budget = total_q - num_seqs`），使单个请求能否推进取决于同批邻居的置信度。因此开启确定性采样时必须关闭变长 MTP，回退到固定长度验证。
4. **结构化输出外围编排与评测真实定位（F10-14, F10-15, F10-16, F10-18, F10-19）**：
   - 结构化输出语法引擎来自上游 xgrammar，DeepInfer 自研的是异步线程池编译与 CPU 掩码流水线（每请求 16 KB pinned bitmask，H2D 专有流搬运，GPU 仅执行 TileLang 负无穷填充）。投机解码联动时预推 k+1 份掩码并在拒绝时调用 `rollback`。
   - 引擎用 60 个浮点数的 PPL 全等指纹（`offline_decode_ppl.json`）、KL=0、64 序列全等严格看守内核改动；而官方公开的 AIME 99.9%、GPQA 93.4% 评测成绩来自开启变长 MTP、关闭批不变性的最快非确定性生产路径。

## 2. aha 候选（最反直觉的点）

1. **同一个请求，旁边换了一个"邻居"，输出就可能变**：
   - 两个完全相同的请求，一个单独跑，另一个跟 300 个长文本请求拼在同一个批次里，算出的 logits 在第 6 位小数就会出现 1 ulp 差异。在 top-p 截断边界上，这 1 ulp 的微小起伏就会让采出的 token 发生分叉。
2. **确定性采样的随机数发生器不看"这是第几步"，只看"这是第几个 token"**：
   - 步数会因为抢占、调度、重放而改变，但 token 在整个长上下文中的绝对位置永远不变。把随机流坐标绑在绝对位置上，是保证重放完全可信的根本解法。
3. **公开的高分评测与可复现的确定性模式在现实中是两条互斥路径**：
   - 官方评测脚本为了追求吞吐和算力利用率，强制打开变长 MTP、默认关闭批不变；想要 100% 逐位复现，就必须关闭变长 MTP 并承受批不变带来的性能损失。

## 3. 观众最容易误解的地方

1. **误解：批不变性只需要在 PyTorch 里设置 `torch.manual_seed()` 即可**。
   - **真相**：PyTorch seed 只能固定随机数，管不了底层 GPU kernel 在不同 batch 下的动态分块和归约树结构。没有内核层的 split-KV/split-K 封印和定点 CDF 直方图，固定种子依然会输出不同文本。
2. **误解：结构化输出是 DeepSeek 完全自研的语法解析器**。
   - **真相**：语法自动机与 bitmask 核心来自开源项目 xgrammar；DeepInfer 自研的是围绕推理引擎的线程池异步编译、CPU pinned 内存池、专有 CUDA 拷贝流与投机解码 rollback 回滚编排。
3. **误解：昇腾芯片上已经完整支持了与 NVIDIA 相同的批不变性与确定性重放**。
   - **真相**：昇腾虽然实现了同构的绝对位置定序采样器，但在算子层目前开启批不变性会直接触发断言报错（`assert not DEEPINFER_BATCH_INVARIANT`），端到端跨批确定性仅对 NVIDIA 承诺。
