## 1. 最重要的 5 个发现

1. **调度器彻底 C++ 化是最大的结构性分水岭**：`Scheduler`、`BlockManager`、`Sequence` 全部驻留在 `csrc/engine/`，由 pybind11 导出为 `deepinfer._C.engine`。Python 层的 `LLMEngine.step()` 只负责装配输入与驱动，调度过程全程释放 GIL，彻底消除了解释器与 GC 开销（F04-01、F04-14）。
2. **代码的绝对重心在算子层，而不是调度逻辑**：`deepinfer/` 约 4.7 万行代码中，`tilelang_ops/` 就占了 23,331 行（49.5%）；NVIDIA CUDA（4,968 行）与华为昇腾 Ascend（7,418 行）两套镜像各 30 个文件平行维护（F04-02、F04-03）。
3. **vLLM 血统仅占 12.4%，属于"保留骨架、换掉芯片"**：带 `Derived from vLLM` 头部声明的文件恰好 23 个、合计 6,817 行，全部位于胶水层；核心模型结构、全部算子库、C++ 调度核心 0 行 vLLM 代码。API 指纹显示其骨架冻结于 vLLM v0.2.x 时代（F04-04、F04-05）。
4. **控制面 RPC 是单向无返回的广播通道**：driver 通过 10 块各 1 MiB 的共享内存环（`MessageQueue`）向 Worker 发送 `(method, kwargs)`，从属 Worker 执行完直接进入下一轮循环，不回传任何结果。采样与输出处理只在 driver 发生（F04-13、F04-21）。
5. **系统彻底去除了张量并行（TP），跨卡仅用 CP/DP/EP**：单引擎实例只管理 `cp_size` 张卡；DP 副本之间每步调用一次 `_dp_allreduce` 投票，统一步型为 prefill 或 decode，防止 EP 专家并行 all-to-all 通信死锁；没有就绪请求的 rank 执行占位陪跑步（F04-11、F04-12、F04-15、F04-16）。

## 2. aha 候选

| 反直觉的点 | 为什么反直觉 | 证据 ID | 可以怎么画 |

| **driver 到 worker 的 RPC 只广播方法名，不回传任何结果** | 传统 RPC 都有请求与响应；这里 driver 只单向发 `(method, kwargs)`，follower 纯执行，采样结果只在 driver 产生 | F04-13、F04-21 | 箭头从 driver 射向 followers，带方法名信封；回程箭头打大红叉，下方标"无返回值" |

## 3. 观众最容易误解的地方

| 误解 | 真相 | 事实 ID |
| --- | --- | --- |
| DeepInfer 是从最新版 vLLM 直接 fork 的完整系统 | 骨架冻结在 vLLM v0.2.x（2023年底），仅 23 个胶水文件（12.4%），核心调度器重写为 C++，模型与算子全自研 | F04-04、F04-05 |
| DeepInfer 可以直接当在线 API 服务拉起并流式对话 | 开源版仅包含离线批量引擎与基准测试，无 AsyncLLM，无流式，无 OpenAI 兼容 HTTP 服务 | F04-07、F04-08 |
| 多卡推理用的是常见的 Tensor Parallel（TP）切矩阵 | 仓库里没有任何 TP 通信组；多卡仅做上下文并行（CP）、数据并行（DP）与专家并行（EP） | F04-12 |
| CUDA Graph 捕获了完整的推理步骤（包含采样与 prefill） | 仅覆盖 decode 阶段的主模型 forward；prefill 与采样均走 eager 模式 | F04-20 |
| C++ 调度器是为了单线程执行跑得更快 | 主要目的是为了在释放 Python GIL 的情况下由后台直接修改调度账本，并消除 Python 对象与 GC 开销 | F04-14、F04-22 |
| 仓库默认的 offline_inference.py 可以在普通消费级单卡上跑通 | 默认单机 8 卡 EP8，硬件算力常量硬编码 SM100（2,250 TFLOPS），非匹配硬件初始化直接报错 | F04-09、F04-25 |

## 4. 与大纲的出入

| 大纲说法 | 核验结果 | 建议改法 |
| --- | --- | --- |
| "带 Derived from vLLM 头的文件只占约 12%，全在胶水层" | 实测 23 个文件、6,817 行，占仓库 Python 总行数 12.4%，完全准确 | 标明 23 文件、6,817 行、12.4% 具体数字与胶水层边界 |
| "DP 副本之间每步用一次 all-reduce 投票" | 代码中通过 `_dp_allreduce` 执行两轮投票（ALL 点与 ANY 点），ZOS 下走 CPU/Gloo | 讲清两轮投票的含义与防死锁作用 |
| "driver 到 worker 的 RPC 只广播方法名和布尔参数" | 载荷为 `(method, kwargs)` 元组，除布尔参数外还包含张量字典的扁平键值 | 准确表述为"方法名与轻量参数字典，无任何返回值" |
