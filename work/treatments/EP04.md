- 对大纲的深化与澄清：
  1. **厘清 vLLM 派生真实边界**：带 `Derived from vLLM` 头部声明的文件恰好 23 个、6,817 行，占一阶 Python 代码约 12.4%，全部局限在胶水层（`engine/`、`worker/`、`sequence.py`、`sampling_params.py` 等）；核心模型结构、全部算子库、C++ 调度核心 0 行 vLLM 代码（F04-04）。

  3. **揭开多卡拓扑真相**：DeepInfer 彻底抛弃张量并行（TP），跨卡由 CP、DP、EP 构成；单引擎只管 `cp_size` 卡，主进程 driver 独占调度与采样，从属卡纯执行（F04-11, F04-12, F04-21）。
  4. **DP 投票与陪跑步机制**：DP 副本每步通过 `_dp_allreduce` 投票统一步型为 prefill 或 decode，消除 EP 通信死锁；空闲 rank 必须跑占位陪跑步保持全网对齐（为 EP08 专家并行埋伏笔）（F04-15, F04-16）。
  5. **元数据计算下沉推迟**：C++ 侧只计算 offset 和 len，把海量索引展开推迟到 GPU forward 阶段以节省 CPU 开销（F04-19）。

## 1. 一句话梗概

沿着一次 `LLM.generate()` 的完整代码调用链路，从 `examples/offline_inference.py` 出发穿透 Python 编排层、纯 C++ 调度核与底层镜像算子库，画出 DeepInfer 仓库的全景架构地图与请求全生命周期。

## 2. 核心问题

打开开源仓库到底该从哪读起？一次推理请求在代码里经历哪些文件与函数？DeepInfer 是怎样用 C++ 调度器、单向 SHM 广播和错步流水线驱动 GPU 一刻不停的？

## 3. 看完能说出的三句话

1. 架构三层分流：外层 Python 编排（仅占 12.4% vLLM 派生胶水），核心调度完全下沉至 C++ 并释放 GIL，底层近一半代码是镜像维护的双硬件 TileLang 算子库。（F04-01, F04-03, F04-04, F04-14, F04-23）
2. 多卡无 TP 与单向 RPC：一个引擎进程只管 `cp_size` 张卡，driver 与从属 Worker 之间通过 10 块 1 MiB 共享内存环仅广播方法名与参数，从属 Worker 无返回值，采样由 driver 独占完成。（F04-11, F04-12, F04-13, F04-21）
3. 错步流水线与 DP 投票同步：单步执行严格按 Forward(N) → Post-process(N-1) → Sample(N) 错步重叠以隐藏传输延迟；DP 副本间每步投票统一步型，空闲 rank 跑占位陪跑步以防止 EP 专家通信死锁。（F04-15, F04-16, F04-17, F04-18）

## 6. 冷开场（A / B 版本）

**A 版（代码考古悬念）**：
- 画面：终端代码编辑器拉开，快速浏览 DeepInfer 仓库树。高亮标出 `deepinfer/`、`csrc/` 与 `vendor/`。当检索 `Derived from vLLM` 时，只有 23 个胶水文件亮起，而算子层与 C++ 核心全是自研代码。
- 旁白：
  > 打开 DeepInfer 的代码仓库，很多人以为这不过是又一个 vLLM 的衍生版本。但如果你用脚本扫描全仓四万七千行 Python 代码，会发现一个不可思议的结构反差：带有 vLLM 派生声明的文件只有二十三个，仅仅占了一成出头；而仓库近一半的代码，居然全是成对镜像维护的底层算子！更让人意外的是，最核心的调度器根本不在 Python 里面，它被全盘重写成了纯 C++。打开这个代码库，一次推理请求究竟走过了哪些隐秘的角落？

**B 版（请求穿透悬念）**：
- 画面：从 `examples/offline_inference.py` 中的一行 `llm.generate()` 切入，光点急速下穿，穿过 Python 包装层、跨越 pybind 边界坠入 C++ 调度器，再经共享内存环裂变为多卡并行光束。
- 旁白：
  > 在 DeepInfer 里，跑通一次离线推理只需要写一行简单的 `llm.generate()`。但在这行代码落下的瞬间，底层系统却经历了一场跨语言、跨进程的精密切割：请求在 Python 侧分词，却被移交进纯 C++ 维护的序列队列；主进程发出的广播只有方法名，从属进程连返回值都不用给；甚至当某张 GPU 无事可做时，也必须强行跑一个占位陪跑步。这一行代码到底是如何穿透整个引擎的？

盲选结果：**选 A 版**（见 `work/reviews/EP04_hook.md`）。
理由：A 版直击“代码地图”这一集的立足点，以精确的代码量与 12.4% vLLM 胶水层反差切入，打破观众固有偏见，更自然地牵引出全集对目录架构与内部实现的深度探索。

## 7. aha 时刻

1. **driver 到 worker 的 RPC 只广播方法名与参数，完全不回传任何结果**：颠覆了传统 RPC 请求-应答双向通信的刻板认知。driver 单向发信，follower 默默干活，采样与后处理只在 driver 发生（F04-13, F04-21）。
2. **空闲 GPU 必须跑"陪跑"步**：直觉上无请求的卡应当待机节能，但为了在专家并行（EP）下保证全网 All-to-All 通信拓扑完全对齐，没活干的 rank 也必须跑占位 step 参与通信交换（F04-15, F04-16）。
3. **C++ 只算 offset 和 len，展开留给 GPU**：C++ 调度器在生成元数据时克制到极点，坚决不分配庞大张量，只写下两个整数界限，把展平交给 GPU 的并行前向完成（F04-19）。
