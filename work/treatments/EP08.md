# EP08 剧集方案：并行：注意力用 DP，专家用宽 EP

## 1. 核心定义
- **核心问题**：当一个 MoE 大模型被拆到 64 张卡上时，它是如何实现显存与计算负载平衡，同时又不被 All-to-All 通信拖垮的？
- **看完能说出**：
  1. DeepInfer 舍弃了所有张量并行（TP），全靠 DP 切请求、EP 切专家，并行度天然解耦。
  2. 显存负载靠 EPLB 两级贪心重排，通信通过 NVLink IPC 显存直读实现 NVL 域内“零搬运”成本。
  3. EP 的意义在于牺牲通信复杂度来换取单卡极低的专家权重访存量，是实现交互式超低延迟的关键，而非为了单纯提升峰值吞吐。
- **aha 时刻**：MoE 层内，那 7.4 倍的理论访存削减量，在高并发吞吐数据上却只转化为了 5% 的净提升——这是对“Wide-EP”商业价值的真实折价。

## 2. 站点与前置概念
- **本集站点**：Decode 阶段 -> 并行与专家并行层 (Parallelism & Expert Routing)。
- **前置概念**：
  - (EP01) 推理分 Prefill 与 Decode，通信是瓶颈。
  - (EP05) 调度器对请求分批处理。
  - (EP06) KV Cache 分页管理。

## 4. 冷开场方案
- **版本 A（数据反差导向）**：开场直接对比 EP8 与 EP64 的两张吞吐 Pareto 曲线，指出 EP64 虽然能让单卡读权重减少 7 倍，但在 256 并发下收益却微乎其微。悬念：既然 Wide-EP 无法换来同倍数的吞吐，DeepSeek 为什么还要坚持大规模 EP 分布？
- **版本 B（架构演进导向）**：开场抛出一张显存总布局，问：“如果每张卡只放一个专家，All-to-All 流量会不会把机器撑爆？”然后瞬间展开 EP64 的 All-to-All 拓扑图，展示通信如何巧妙被计算覆盖。
