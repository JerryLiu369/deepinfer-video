## 1. 一句话梗概

对照生产拓扑与开源代码，揭开 DeepInfer“生产离线引擎”的真实定位，标出开源边界与三大缺失在线组件，通过代码中的接口插槽看透现代大模型生产服务的设计蓝图。

## 2. 核心问题

DeepSeek 到底开源了什么？没开源什么？如果想用它对外提供在线 API 服务，中间还隔着哪些工程鸿沟？

## 3. 看完能说出的三句话

1. 开源的是生产引擎的离线推理部分：专为单一模型 DeepSeek-V4.1-Flash 定制，官方仅支持 NVIDIA SM100 与华为昇腾 950 硬件。（F02-01, G-02, G-05）
2. 完整在线云服务还缺失三项关键基建：分布式 KV Cache 存储、VE/Prefill/Decode 三段物理分离部署、以及跨副本在线负载均衡；开源仓库中完整保留了对接这些系统的“架构插槽”。（F02-03, F02-07）
3. DeepSeek 的真实生产系统采用 E/P/D 三段分离与独立 3FS 存储集群；其设计目标是在多厂商硬件上，以 128 卡最小高效单元实现 KV 留存 72 小时以上的大规模高吞吐服务。（F02-04, F02-05, G-07）

## 4. 站点与三源头

- 站点（MiniMap 高亮）：全图（系统全景总览站）
- 三源头（模型 / 部署 / 生产）：
  - 模型：V4.1-Flash 的 SWA 与 YOCO 特性（决定了引擎只支持单模型，需专用调度）
  - 部署：E/P/D 三段物理解耦与 3FS 外置存储（构成了在线服务与离线引擎的明确分界）
  - 生产：低成本、降能耗与双硬件支持（驱动了 TileLang 内核与插槽式架构设计）

## 6. 冷开场

**A（手法：反差悬念 Hook）**——画面：终端里快速执行 `git clone`，满怀期待地寻找 `server.py` 或 `FastAPI` 入口，却发现搜索结果为空；全屏弹出开源代码仅有的离线入口 `examples/offline_inference.py`。

> 很多人把 DeepInfer 的代码克隆下来，第一件事就是寻找启动在线 API 的服务入口。但搜遍整个仓库，你既找不到网络路由，也找不到接口服务。DeepSeek 确实开源了他们每天跑上百万亿 Token 的推理引擎，但它并不是一个拿来就能用的在线云服务。

**B（手法：数字反差 Hook）**——画面：左侧亮出巨大的“每天 155 万亿 Token、每卡每小时 38 美元”，右侧亮出仓库里仅支持一个模型、缺少三大组件的限定清单。

> 每天一百五十五万亿个 Token，每张卡每小时三十八美元的整体营收。这是 DeepInfer 伴随开源放出的惊人生产成绩。然而点开代码，它却只支持一个模型、两款特定芯片，甚至连在线服务必需的三个组件都没有开源。

盲选结果：**选 A**（见 `work/reviews/EP02_hook.md`）。
理由：直接从开发者的真实操作困惑切入（“克隆下来找入口”），以悬念打破“开源等于开箱即用”的认知误区，自然引出本集核心问题：“它到底开源了什么，没开源什么”。

## 7. aha 时刻

- **观众"原来如此"的那一刻**：
  README 里写的“大部分引擎功能已实现”，并不是说分布式传输做完了，而是引擎内部所有的调用接口、调度状态迁移和显存拷贝插槽都已严丝合缝地准备就绪！
- **画面怎么实现**：
  1. 架构代码联动：左侧展示 C++ 调度器完备的状态流转（`prefill_engine won't change status because it will be transferred to complete_engine`），右侧展示 Python 引擎层 7 个空实现的虚函数骨架（`init_pd_split`、`do_save_kvcache` 等）。
  2. 机械插座拼装动画：外部的“KV存储网”和“跨机传输带”拔出，但引擎核心上的“母座插槽”完整保留。
- **紧接着用什么防止误解**：
  立刻说明：这种“留插槽、剥实现”的做法不是偷工减料，而是为了把与内部机房基建强耦合的代码剥离，让开源版保持精简与便携。
