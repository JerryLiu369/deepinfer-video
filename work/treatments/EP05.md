## 1. 一句话梗概

深入解析 DeepInfer 如何通过 ZOS（零开销调度）让 CPU 永远晚一步，在连续解码步中将前向计算、后处理与下一步调度完美重叠，并以极小的固定代价化解输入未知、行序重排与请求结束三大异步难题。

## 2. 核心问题

在每步仅需几毫秒的高吞吐自回归生成中，CPU 的调度开销怎样才能不把价值连城的 GPU 拖入漫长的空闲等待？当 CPU 永远滞后一步时，系统又是如何解决输入 Token 未知、批次行号动态错位以及请求结束状态延迟三大难题的？

## 3. 看完能说出的三句话

1. **ZOS 核心机制与重叠时序**：GPU 运行第 N 步模型计算的同时，CPU 并发处理第 N-1 步的后处理并调度准备第 N+1 步；异步重叠仅在连续 Decode 步生效，Prefill 步仍为纯同步并排空流水线。（F05-01, F05-03, F05-04, F05-05）
2. **GPU 就地捡词与乐观账本**：CPU 根本不为存量请求构造输入 Token，而是由 GPU 上的 TileLang 内核直接从上轮采样张量中捡出；显存块通过 `total_inflight_tokens` 乐观推进并按真实接受数事后回填。（F05-06, F05-07, F05-09, F05-11）
3. **EOS 固定代价与工业界共识**：已结束的请求因 CPU 滞后会多跑一次无用前向，但这仅浪费 0.2% 算力却换来消除 25% 空泡的巨大净收益；该异步重叠思想源自 NanoFlow 与 SGLang，已成为现代生产级推理引擎的行业标准标配。（F05-08, F05-18, F05-19, F05-20, F05-21）

## 6. 冷开场（A / B 版本）

**A 版（GPU 空泡与算力蒸发反差）**：
- 画面：两组对比时间轴。上方是传统同步调度，GPU 在计算完后陷入灰色的长条等待空泡，旁边跳出刺眼的“25% 算力蒸发”；下方是连续无缝运转的 ZOS 流水线，GPU 色块一刻不停。
- 旁白：
  > 在大模型生成阶段，一块顶级的 AI 芯片执行一次前向计算只需要短短四毫秒。然而在传统的推理引擎里，GPU 跑完这四毫秒后，却不得不停下来等待 CPU 完成后处理与下一轮调度。这看似不起眼的一点五毫秒停顿，竟然让昂贵的算力凭空蒸发了近四分之一！为了让 GPU 一刻不停，DeepInfer 采用了一种极具侵略性的策略：让 CPU 永远晚一步。这种“滞后一步”的系统究竟是如何运转的？那些还没被算出来的下一个词，又该怎么提前送进 GPU？

**B 版（时间旅行悬念）**：
- 画面：时钟逆转，一个带有问号的输入数据包强行穿越时空，在上一轮结果尚未返回时就提前送入 GPU 模型计算流，随后镜头拉开揭示双层齿轮交错咬合的机械时钟。
- 旁白：
  > 如果你问一个程序员：能不能在不知道上一个字输出是什么的前提下，就提前把下一个字送进模型计算？大多数人会觉得这违背了物理因果律。但在 DeepInfer 的调度世界里，这种看似不可能的“抢跑”不仅真实发生，更是它压榨吞吐的核心武器。当 CPU 的决策时钟永远落后于 GPU 时，系统该如何跨越因果顺序的混乱？

盲选结果：**选 A 版**（见 `work/reviews/EP05_hook.md`）。
理由：A 版以严谨精准的量化数据（4 毫秒计算 vs 1.5 毫秒空闲，25% 算力蒸发）切入，直击生产级性能痛点，自然引出“让 CPU 永远晚一步”的核心矛盾与悬念，完全契合硬核科普的技术底色。

## 7. aha 时刻

1. **CPU 根本不构造存量请求的输入 token，GPU 在显存里就地“捡词”**：观众通常认为调度器必须准备好每个请求的输入数据。真相是在 ZOS 下，CPU 连一个字节都不写，而是由 TileLang GPU 内核从上轮采样张量里就地切片重组，彻底打破“CPU 喂数据、GPU 吃数据”的思维定势（F05-06）。
2. **EOS 结束请求必须多跑一步，但算力损失仅千分之二**：直觉上以为遇 EOS 必须当场截断，否则是巨大浪费。通过严密的算术账本证明：多跑一步仅损失 0.2%，却换来全流程消除 25% 调度空泡。这是反直觉却极其明智的工程代偿（F05-08, F05-21）。
3. **文档写得神乎其神的二次时间配额，代码里居然全是硬 Token 计数**：文档与源码的戏剧性反差，代码中的二次方程仅用于打印日志 MFU，让观众真正体会到“只读文档会被骗，源码才是唯一真相”的代码现实主义（F05-14）。

## 9. 暂停题与标准答案

- **问题**：如果第 N 步某个请求已经输出了结束符（EOS），而 CPU 在 ZOS 异步调度下已经把它排进了第 N+1 步，底层系统会发生什么？为什么不当场中断？
- **标准答案**：
  1. **发生什么**：因为 CPU 滞后一步不知道它已输出 EOS，该请求会在第 N+1 步多跑一次前向计算（以 EOS 作为输入 Token）；在第 N+1 步的后处理中检测到 `is_finished()`，直接丢弃该次前向输出并释放 MTP 槽位，最终在第 N+2 步将其移出运行队列并释放显存块。（F05-08）
  2. **为什么不当场中断**：若要当场中断，CPU 必须在第 N 步采样结束时阻塞等待 GPU 结果，从而重新引入 25% 的调度空泡。以 500 token 序列为例，多跑 1 步仅浪费 0.2% 算力，以千分之二的微小代价换取消灭四分之一的空转等待，是吞吐最大化下的必然取舍。（F05-08, F05-21）
