## 1. 观众复述三要点（看完能说出的三句话）

1. **开源范围非常聚焦**：DeepInfer 开源的是生产引擎里的离线推理部分，专供单一模型 DeepSeek-V4.1-Flash，官方只支持英伟达 SM100 和华为昇腾 950 两款芯片。
2. **完整服务还缺三样基建**：要搭一个真正的在线 API 服务，还缺分布式 KV 存储、预填充与解码物理分离、以及跨副本负载均衡；代码里完整保留了对接这些系统的虚函数插槽。
3. **真实生产架构是三段分离加独立存储**：DeepSeek 生产环境是 Entrypoint 入口、Prefill 8卡机、Decode 64–128卡超节点三段分离，底下连着保留 72 小时以上、每卡配比 14.4TB 的独立 3FS 存储集群。

## 2. 自测题作答（由 showrunner 出题，viewer 盲测回答）

### 题目 1：DeepInfer 开源出来的版本，能直接用来部署一个对外提供服务的在线 API 吗？为什么？
- **作答**：不能。因为开源版本只提供了单机离线批处理推理能力（`LLM.generate`），仓库里完全没有网络服务入口、请求排队、路由网关以及跨机分布式存储传输等在线云服务必需的基础设施。（S01, S03, S07）

### 题目 2：DeepInfer 官方目前明确支持哪些模型和哪些计算芯片？
- **作答**：模型只支持单一模型 DeepSeek-V4.1-Flash；硬件目前官方只支持英伟达 SM100 GPU 与华为昇腾 950 NPU。（S03, S04, S05）

### 题目 3：要组成一个完整的线上云服务，官方 README 明确指出开源版缺失哪三样核心基建？
- **作答**：缺失三样：第一是分布式 KV Cache 存储管理系统；第二是预填充（Prefill）与解码（Decode）的物理分离部署机制；第三是跨数据并行副本的在线请求负载均衡器。（S06, S08）

### 题目 4：DeepSeek 真实的生产系统采用了怎样的整体拓扑架构？最小的高效服务单元是多少张卡？
- **作答**：生产系统采用 E/P/D（Entrypoint / Prefill / Decode）三段分离拓扑，底层接入专用 3FS 分布式存储集群。最小的高效服务单元是 128 张卡（64 张 Prefill 卡加 64 张 Decode 卡）。（S09, S10, S13）

### 题目 5：既然开源版没有跨机网络传输和存储读写代码，为什么官方会说“大部分引擎功能已经实现”？
- **作答**：因为引擎内部把所有与外部系统对接的“架构插槽”与调度状态机都做完了：包括 EngineType 三态枚举、7 个空实现的虚函数骨架、C++ 调度器里的移交判定（`prefill_engine ... transferred to complete_engine`）、以及显存状态副本缓冲区 `copy_state`。只是因为这些组件与内部机房基建强耦合，具体实现暂时留空剥离。（S15, S16）
