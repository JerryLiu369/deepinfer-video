## 3. 账本本身的问题（交 showrunner 转 fact-checker）

1. **F03-27 的“每层”要改。** `claim` 写“每个 token 每层只查 3 阶 × 8 head = 24 行”，但 Engram 只在 `engram_layer_ids=[1,14]` 两层（F03-25 conditions、`config.py:208`、`deepseek.py:114`）。应改为“每个 token 在每个 Engram 层查 24 行”，否则 S06 的“每层”会被账本背书。研究简报 §1 第 4 条也有同样的“每层”，一并改。
2. **F03-17 的“落盘”与 dropped 语义要加 caveat。** 官方文档写 SWA KV cache → Local host memory，`nothing on 3FS`；`state_size_to_disk` 是“写进 state store（本地 host 内存）”，不是 3FS 磁盘。另外 dropped region 仍随 PE→CE 完整 state 传输（`cache_engine.py:780,790-800`），不是运行时丢弃。建议在 F03-17 的 caveat 里写清这两点；S16 的“分布式存储集群/直接扔掉”就是这两处缺失导致的。
3. **F03-34 的等级混了 A/B。** `claim` 同时包含代码默认（A）和“官方文档描述生产使用变长验证”（B），但整条标 A；S19 的“生产主力启用”又引了不相关的 F03-36（B）。建议拆成 F03-34a（A：默认关闭、置信度头、采样兜底）和 F03-34b（B：生产变长验证，doc:243/247），或在 caveat 里标明 B 级部分。F03-29 也有同类问题：“Single-Pass mHC”是报告命名（B），代码部分（hc_mult=4、20 次 Sinkhorn）才是 A；建议在 caveat 里分开。
4. **EP03 缺 140/KEEP_TOKENS 的事实条目。** S20/S21 用了“140 行”，但 EP03 账本没有一条 `claim` 覆盖 `KEEP_TOKENS`；只有 F03-15 的 caveat 提了 140（还是 EP07 的设置）。要么新增一条事实（`README.md:25`、`environ.py:188-194`、下限 134），要么把脚本里的 140 改成“末尾一小段”。按 06 §1 规则 2，134（存储/命中口径）与 140（保留行数设置）应同时上屏、讲清差异。
5. **S07/S19 的 F03-36 引用是错配，不是账本错。** F03-36 不含 mHC/变长验证；但账本没有对应条目可引，建议补一条 mHC 命名（F03-29 已有）或把 S19 的 doc 句单独入账。

## 4. 三句话总结

1. 数字账本基本可靠：890 / 288 / 68 / 178 / 356 / 113,920 / 3.13 MB / 1.35 MiB / 3,516 / 28 块全部复算一致；但“层数口径”有三类会直接被观众记住的错误——S01/S12 的“四层”、S06 的“每层”、S12/S20/S22 的“后二十层”。
2. 最严重的叙事错误在 S16：SWA state 是本地 host 内存、不进 3FS，dropped region 也不是“直接扔掉”（PE→CE 仍传完整 state）；这两句把官方文档的存储分层讲反了，而且 badge 仍标 A。
3. 其次是 134/140 与 S10 的报告误读：140 是 README 设置、代码默认关闭、下限 134，且第 20 层仍做全长投影；报告说的是“从第 20 层 hidden 投出、每层用自己的权重”，不是“每层独立投影”。
