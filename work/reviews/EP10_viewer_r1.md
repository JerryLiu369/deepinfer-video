## 观众审读附加项

- 第一次出现却没解释的术语：无，所有出现的专用概念（split-KV、CTA、bitmask、rollback 等）均有上下文递进阐释。
- 看完的疑问（"那为什么不……？"）：
  - 问：既然确定性模式可以彻底消除舍入漂移，为什么生产服务不默认开启？
  - 答：正如 S08、S09 和 S13 所述，批不变性要求关闭 split-KV、禁 split-K 并关掉变长投机，小批次下会导致 GPU 算力闲置，生产环境为了追求极限吞吐（TPOT 和并发量）默认走最快的非确定性路径。
- 觉得多余的镜头：无，18 个镜头节奏饱满，从双硬件底座、浮点本质、确定性绝对坐标、结构化输出到测试评测防线层层递进。
- 用自己的话复述三句话：
  1. DeepInfer 依托 5 个外部库与自研 TileLang 算子，在构建期用同名镜像屏蔽了英伟达和昇腾的硬件分歧。
  2. 浮点加法非结合律导致动态合批改变了归约树，批不变模式通过关掉 split-KV、禁 split-K 与定点直方图把批维度剥离。
  3. 确定性采样把随机数绑在 token 绝对位置上，而变长投机解码因全局排名争夺预算破坏了独立性，确定性模式必须将其关闭。
- 自测题作答：
  1. 题：为什么相同的 Prompt 和种子在合批后可能输出不同结果？
     答：因为浮点加法不满足结合律，合批大小改变了 GPU 并行归约树的分块与求和顺序，产生的 1 ulp 舍入漂移在采样边界引发分叉。（答对）
  2. 题：DeepInfer 是如何让上层代码无缝支持英伟达与昇腾双硬件的？
     答：在构建阶段通过脚本编译同名 wheel 包，上层统一导入，TileLang 算子在底层分别维护 43 个同名工厂并由 ops.py 动态重导出。（答对）
  3. 题：开启批不变性在算子层面具体做了哪些外科手术？
     答：FlashMLA 关 split-KV、DeepGEMM 禁 cuBLASLt 与 split-K、DeepEP 禁多次归约、采样器一行一个 CTA 且用 2^31 定点直方图求阈值。（答对）
  4. 题：为什么开启确定性采样时必须关闭变长 MTP？
     答：变长 MTP 把全批请求的草稿按置信度全局排名分配预算，单个请求的验证长度受其他邻居影响，破坏了独立性。（答对）
  5. 题：结构化输出是如何在 CPU 和 GPU 之间分工合作的？
     答：CPU 异步线程池负责编译 xgrammar 自动机并生成 16 KB 的 pinned 位掩码，专有流送入 GPU 后由 TileLang 快速把非法 token 的 logits 填成负无穷。（答对）
