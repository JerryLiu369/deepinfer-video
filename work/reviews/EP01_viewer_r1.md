## 1. 复述三句话

1. 大模型推理分为两步：第一步预填充把提示词一次性吃完，GPU 核心全力满载计算；第二步解码是一步一步生成单个词，核心算得极快但大部分时间在等显存把权重送过来。
2. KV 缓存保存了过去所有 token 的向量，免去了重复计算，但它会随着对话轮数和并发请求线性暴增，是制约显存容量的硬天花板。
3. 推理引擎的核心使命就是在首字延迟、生成步长和系统吞吐三者之间做权衡，利用批处理、动态连续调度、专家并行和投机解码来压低单 token 成本。

## 2. 5 道自测题作答

1. **大模型推理为什么在物理上被拆分为预填充（Prefill）和解码（Decode）两个阶段，各自受限于什么硬件瓶颈？**
   - 作答：因为预填充是把用户的整段输入矩阵一次性送入核心，矩阵乘尺寸大，算术强度高，属于算力受限（Compute-bound）；而解码每步只输入当前 token 逐字生成，每生成一个词就要把数十 GB 权重全读一遍，属于显存带宽受限（Memory-bandwidth bound）。两者物理资源需求截然相反。（出处：S04–S06）
2. **为什么在单请求解码时，算力高达上千 TFLOPS 的 GPU 核心大部分时间在闲置等待？**
   - 作答：因为单请求解码时每步计算量极小（如 32 GFLOP 只要 0.032 毫秒），但读取 16 GB 权重需要整整 5.0 毫秒，算术强度只有 2.0 FLOP/Byte，计算核心只能空转等待显存总线把数据搬过来。（出处：S06–S07）
3. **解码阶段把 Batch Size 从 1 提升到 64，为什么单个 Token 的生成成本会大幅下降，而步长耗时几乎不变？**
   - 作答：因为在带宽受限下，单步加载一次 16 GB 权重需要 5.0 毫秒，这 5.0 毫秒是固定开销；打包 64 个请求后，这一轮加载的权重同时给 64 个 token 共用计算，算力利用率从 0.6% 提升到 40.8%，总耗时依然只有约 5.0 毫秒，但产量翻了 64 倍，每个 token 的硬件成本被极大地均摊。（出处：S08–S09）
4. **什么是 KV Cache，为什么说它是决定推理系统并发容量与上下文长度的核心瓶颈？**
   - 作答：KV Cache 是历史所有 token 计算出的 Key 和 Value 向量缓存，用来避免每步从头重算历史注意力；它会随着并发请求数和序列长度成倍线性膨胀，在长上下文时显存占用远超模型权重，直接锁死了单机能容纳的请求上限。（出处：S10）
5. **传统静态批处理有什么缺陷，连续批处理（Continuous Batching）是如何解决这一缺陷的？**
   - 作答：静态批处理要求所有请求同进同出，短请求早早结束后必须原地等待长请求，产生巨大的空转气泡；连续批处理在每一个 step 动态调度，请求做完了立刻释放移出，新请求立刻插入，消除了等待气泡。（出处：S11–S12）
