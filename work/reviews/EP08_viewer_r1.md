# EP08 观众模拟与理解报告 (r1)

- 评审对象：`work/scripts/EP08.md`
- 角色：代表技术受众与委托人
- 复述三句话：
  1. DeepInfer 彻底丢掉了张量并行，注意力按数据切，专家按卡切。
  2. 调度器每步靠投票对齐步调，没活的卡跑 1-token 假请求陪跑。
  3. 宽 EP 并不是为了高并发吞吐翻倍，而是为了在低并发下以极少权重访存换取极速交互。
- 5 道自测题回答：
  1. DeepInfer 生产有没有 TP？答：没有，只有 DP 和 EP，model parallel 等同于 CP。
  2. DP 各卡批次不一样大怎么做集合通信？答：每步投票决定步型，没活的卡跑 1-token placeholder 陪跑。
  3. 共享专家输出怎么归约？答：直接作为 bias 传入 DeepEP combine 融回收尾。
  4. NVLink 域内 EPLB 如何搬运专家权重？答：通过 symm_mem 和 CUDA IPC 直读对端显存镜像，无 P2P 消息。
  5. Wide-EP 高并发下为什么增益只有 5%？答：因为全卡聚合批增大，瓶颈从 HBM 访存转移到了通信与启动开销。
- 结论：放行（5/5 正确）。
